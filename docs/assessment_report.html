Architecture

Modular subpackage architecture with clean separation of concerns. Each boundary is a protocol-based interface injected via the application factory, enabling independent testing and production swaps without cascading changes.

Registry Layer

Adapter Layer

Execution Layer

Retry loop, exponential backoff, timeout enforcement

Trace Layer

In-memory store with TTL expiration and ownership isolation

Simulation Modes

The mock adapter supports 6 simulation modes, enabling deterministic testing of every failure path without external dependencies. Each mode is selected per-request via the simulation field.

Mode Adapter Behavior HTTP Error Code Retry?
ok Returns fixture result immediately 200 — No
transient_then_ok Fails 2x, succeeds on attempt 3 200 — Yes (recovers)
transient_always All 3 attempts fail with transient error 503 UPSTREAM_UNAVAILABLE Yes (exhausted)
permanent_error Non-retryable error on first attempt 502 UPSTREAM_PERMANENT No (fatal)
malformed_result Returns invalid schema 502 INVALID_TOOL_RESULT No (schema)
timeout 2s sleep, 250ms timeout enforced 504 UPSTREAM_TIMEOUT Yes (all timeout)

Security Model

Enforced Constraints

✓
Token-only identity
X-Tenant-ID, X-Scopes headers are ignored. Principal comes from bearer token only.
✓
Pre-adapter scope check
403 returned before adapter is ever called. No wasted computation on unauthorized requests.
✓
Body field isolation
Unknown fields (user_id, tenant_id, scopes) in the request body are silently ignored.
✓
Trace ownership
Same user + same tenant required. No admin bypass. Unknown traces return 404.

Information Hiding

✓
No stack traces in errors
Error responses contain structured error codes and safe messages only.
✓
No tokens in traces
Bearer tokens, raw message text, and tool payloads are redacted from stored traces.
✓
Debug log redaction
Structured JSON logging redacts bearer tokens, message text, and tool-result bodies.
✓
No baked credentials
Docker image contains no credentials. Fixture data is for demo scenarios only.

Production Migration Paths

OIDC Identity Provider

service/identity/resolver.py

Replace IdentityResolver with a JWTIdentityResolver that validates JWT signatures against the OIDC provider's JWKS endpoint, extracts sub, tenant_id, and scope claims. The Principal dataclass and all downstream code remain unchanged because the resolver is a protocol-based interface injected via the factory.

MCP Tool Server

service/adapter/mock_adapter.py

Replace MockToolAdapter with an MCPToolAdapter that establishes MCP client sessions and calls session.call_tool(). The execution engine's retry, timeout, and trace recording logic is completely decoupled from the adapter and remains untouched. YAML tool declarations already map to MCP tool discovery.

Redis Trace Store

service/traces/store.py

Implement RedisTraceStore with the same store()/get() interface. Enables trace persistence across restarts, horizontal scaling with multiple workers, and native TTL expiration via Redis EXPIRE instead of lazy cleanup.

LangGraph Agent Integration

service/agents/base.py

System prompts are externalized in YAML, tools follow a protocol mapping to LangChain's BaseTool. Each agent exposes system_prompt + tools — a LangGraph StateGraph node consumes both. The gateway's retry, timeout, tracing, and auth layers remain completely untouched.

Key Design Decisions

Why Mock Agents, Not LangChain?

The assessment mandates docker run --rm --network none, which prohibits all outbound network calls. A LangChain/LangGraph agent would call an LLM API on every invocation, violating this constraint. Mock agents with fixture data keep the execution harness fully testable and deterministic while making the LLM integration a single-adapter swap.

Why Protocol-Based Interfaces?

Python Protocols enable structural (duck) typing without requiring inheritance. This means any class with the right properties satisfies the contract — both mock agents (fixture-backed) and future LLM agents (LangGraph StateGraph) can be used interchangeably without modifications to consuming code.

Why Injectable Sleep?

The retry policy uses exponential backoff (50ms, 100ms delays). Injecting the sleep function lets tests replace asyncio.sleep with an instant mock, making 40 tests complete in 0.75s instead of waiting for real delays. Retry timing is verified by asserting the exact arguments passed to the mock.

Why Read-Only Retry?

Read-only operations are inherently idempotent — repeating them has no side effects. Billing mutations are not idempotent: retrying after a timeout could double-charge a customer. Automatic retry of mutations requires idempotency keys and server-side deduplication, which are out of scope for this assessment.
